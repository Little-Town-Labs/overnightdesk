# Role-Based Ringer Delivery Extension

This local Spec Kit extension adds a checked delivery decision between
`analyze` and `implement`.

- `speckit.ringer-delivery.prepare` classifies context, scale, and risk; records
  graph evidence; and generates a durable `delivery.md` plus scratch Ringer
  manifests.
- `speckit.ringer-delivery.run` executes only the prepared route, keeps
  sensitive and production mutation with the accountable lead, and enforces
  the bounded quality loop.

The checked generator, not the human gate alone, enforces brownfield graph
evidence. It rejects brownfield feature/system requests unless graph status is
`ready` and at least one evidence item is recorded. The extension therefore
keeps `codebase-memory-mcp` conditionally optional for greenfield and micro work.

The implementation worker handles routine implementation and the routine
reviewer handles bounded advisory review. The quality reviewer owns the
distinct final quality gate. The global policy's authoritative blocker taxonomy,
finding dispositions, scope decisions inside approved work,
protected authorization boundaries, and stable delivery roles govern these
routes.

Install locally from a project root:

```bash
specify extension add --dev "$HOME/.local/share/ringer-workflows/extension/ringer-delivery"
```

Before executing a generated manifest, run structural lint and a
configuration-aware dry run. For `implementation.manifest.json`, use its
package's generated `implementation.config.toml` as the `--config` argument
in both commands below. Read-only and quality manifests use the installed
managed config shown here; that config intentionally cannot resolve the gated
implementation engine:

```bash
RINGER_HOME="$HOME/.local/share/ringer/performance" \
python3 "$HOME/src/ringer/ringer.py" \
  --config "$HOME/.local/share/ringer-workflows/config/config.toml" \
  lint <manifest.json>
RINGER_HOME="$HOME/.local/share/ringer/performance" \
python3 "$HOME/src/ringer/ringer.py" \
  --config "$HOME/.local/share/ringer-workflows/config/config.toml" \
  run <manifest.json> --dry-run --no-dashboard
```

Lint verifies that manifest engine names exist in the selected configuration.
The dry run remains required as separate command, path, model, and effort
evidence.

The extension intentionally does not replace core Spec Kit templates. Project
constitutions and repository `AGENTS.md` instructions remain authoritative.
The absolute source path in local installation metadata records provenance;
execution uses the project-local installed workflow. Machine-local tool paths
remain intentional until this overlay receives an approved organizational
remote.

For Spec Kit mutable manifests generated by profile 1.1.0+, use the package's
`implementation.config.toml` for lint, dry-run, and execution. It wraps the
configured implementation worker with the per-task prerequisite, environment,
and assertion-RED gate; the ordinary role config intentionally cannot launch
that gated engine. Lead implementation uses the same `task_gate.py run` entry
point. See the installed overlay's `schemas/task-gate-contract.md` for the
accepted contract. Older ungated packages must be regenerated before use.
